RAMVORA is a business-to-business service. For the documents our customers upload, the **customer
is the controller** and RAMVORA acts as a **processor/service provider** on the customer's
instructions (see the Data Processing Addendum). For our own account, billing and security
records, RAMVORA is the controller.

## 1. Information we process

| Category | Examples | Source |
|---|---|---|
| Account and billing | Email address, plan, account status, Stripe customer and subscription IDs | You, Stripe |
| Credentials | A **hash** of each API key (never the key itself); short-lived encrypted copies used only to deliver a new or recovered key | Generated by us |
| Usage and security | Page counts per month, request timestamps for rate limiting, failed-login/invalid-key events, admin audit records with a non-reversible client fingerprint | Generated when you use the Service |
| Billing events | Stripe event IDs and types (payment succeeded/failed, refund, dispute) | Stripe |
| Documents you upload | Invoice text, PDFs and images, and the data extracted from them | You |
| Email delivery | Whether a key or recovery email was sent | Resend |

We do not ask for and do not want sensitive categories of personal data. Invoices can contain names
and business contact details of the people listed on them; that is Customer Data processed on the
customer's behalf.

## 2. Documents you upload

Uploaded files and text are processed **in memory** to produce the result and are **not stored**
after the request completes. Extracted results are returned to you and are not kept by the API.
Application logs record request metadata (time, path, status code), **not** document contents, API
keys or payment details.

> **Reviewer note:** confirmed in code and Render logs (2026-11-26). Usage is metered by page count
> only. If error-monitoring tools are added later, they must be configured not to capture request
> bodies.

## 3. How we use information

- To provide the Service: authenticate requests, extract data, meter usage, deliver API keys.
- To bill and administer subscriptions (with Stripe).
- To secure the Service: rate limiting, abuse prevention, fraud and chargeback handling, audit logs.
- To support you and send service and transactional messages.
- To comply with law and enforce our Terms.

We **do not sell** personal information, do not use it for advertising, and **do not use customer
documents to train machine-learning models**.

## 5. Retention

| Data | Retention |
|---|---|
| Uploaded documents and extracted results | Not stored (processed in memory) |
| Request timestamps used for rate limiting | About 1 hour, then deleted automatically |
| Public rate-limit events (e.g. invalid key attempts) | About 24 hours, then deleted automatically |
| Recovery codes | Expire after 10 minutes |
| Account, usage and billing-event records | While the account exists; deleted when you delete the account (except as below) |
| Admin audit log | [PERIOD, e.g. 2 years]: currently kept indefinitely |
| Encrypted backups | Server copies: 7 daily, 4 weekly, 12 monthly. Off-site copies: deleted automatically after 400 days |
| Stripe payment records | Kept by Stripe as required by law |

**Deleted accounts in backups:** after deletion, an account's records can remain inside encrypted
backups until those backups expire (up to 400 days). Backups are used only to restore the
Service after a failure.

> **Reviewer note:** decide a fixed audit-log period, and whether 400 days of backup retention is
> acceptable or should be shortened (e.g. 90 days).

## 6. Security

- Data in transit is encrypted with TLS (HTTPS is enforced).
- API keys are stored only as hashes.
- Backups are encrypted (AES-based Fernet) before upload, with a key held separately from the
  service's other keys.
- Admin access requires a long secret key and has lockout and audit logging.
- Access to infrastructure accounts is limited to authorised personnel.

No system is perfectly secure. Report security issues to support@ramvora.io.
